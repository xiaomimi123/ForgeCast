# 截图排版成片（模板 shots）设计

> 日期：2026-07-24　状态：设计已确认，待实施
>
> 属于「视频出片」子系统（A 块）的 A2 项。A1（字幕口径统一 + 真配音接通）与 A3（录屏自动剪辑）均卡在外部 key，另行设计。

## 问题

用户看到的唯一一条成片是 `flash-pain-*.mp4`，判断「没字幕没配音」。核查结果：

- `Flash.tsx` 里 `Audio` / `Subtitles` 出现 0 次——这套模板设计上就是纯文字动效的 15 秒短片，本来就没有音轨和字幕。
- `Story.tsx` / `Demo.tsx` 各有 4 处引用，字幕与配音都接了线，但从未渲染过成片。
- 即便渲染，`FORGECAST_TTS_MODE=stub` 下 `synthesizeVoice` 写的是 44 字节静音 WAV，所以是哑的。

真正的产品缺口是：**用户手上没有 3-5 分钟录屏，Demo 模板跑不起来**；而手上有的产品截图，现有三套模板都用不上。本设计补这条路。

## 方案

新增第四套模板 `shots`，不改动现有三套。命令 `forgecast video <slug> --tpl=shots`。

### 素材约定

`workspace/<slug>/shots/` 下放图片，按文件名字典序排（`01.png`、`02.png`…），支持 png / jpg / webp。

**找不到目录或目录内无图片时直接报错退出**，不像 Demo 那样渲一个虚线占位框继续出片。这套模板没图就没有存在意义，静默出片只会浪费一次渲染。

### 片子骨架

沿用 Demo 的五段结构，只替换中间的演示段：

```
钩子(90帧) → 痛点(150帧) → 截图轮播(1110帧) → 报价锚点(210帧) → CTA(240帧)
                              ^^^^^^^^^^^^^^ 这段从 OffthreadVideo 换成截图轮播
```

前后四段原样复用 Demo 的实现。文案侧零改动——同一份 `douyinScript` 与 props 直接喂进来，不必为新模板改提示词。

### 配音与字幕

复用 story/demo 既有路径：调 `synthesizeVoice` 拿 wav + cues，挂 `<Audio>` + `<Subtitles>`。

因此 TTS key 配好后这套自动获得真人声；**当前渲染就已有字幕**（字幕来自文案切句，不依赖 TTS），只是音轨为静音占位。

### 演示段画面

**时间分配**：演示段总帧数 ÷ 图片数，每张平均停留。不设上下限——图给少了每张停很久是用户的选择，系统不代为判断。

**单张图渲染**：

- **竖图**（宽高比 < 1）→ 手机外框居中，图铺满机身内屏。外框用纯 CSS 画（圆角矩形 + 边框 + 顶部刘海条），不引入外部素材，保证 Docker 内可渲。
- **横图**（宽高比 ≥ 1）→ 回落为居中缩放 + 同图放大虚化作背景。用户材料以竖图为主，但混入横图不能让画面崩掉。
- **运镜**：`scale` 1.0 → 1.06 缓慢放大。死画面完播率差，但幅度必须小，大了会晕。
- **转场**：相邻两张交叉淡入淡出约 0.4 秒。

**比例判定**：Remotion 组件内拿不到图片尺寸，故在 `buildShotsProps` 阶段用 Node 读图片头解析宽高（png/jpg/webp 的宽高均在文件前几十字节内，不引入图像库），把 `orientation` 算好写进 props。组件层保持纯渲染、可单测。

### 时长对齐

沿用 `Root.tsx` 既有的 `calculateMetadata`：按 cues 末尾时刻拉长总时长。旁白多长片子就多长，不会出现旁白没讲完画面先黑。

## 测试

| 层 | 用例 |
|---|---|
| props 构建 | 图片 0 张（报错）/ 1 张 / N 张的帧分配；文件名排序；非图片文件被忽略 |
| 尺寸读取 | png / jpg / webp 三种格式的宽高解析；损坏文件按横图兜底不崩 |
| 渲染 | stub 模式跑通（同现有三套模板的测法） |
| 真渲 | 造测试竖图真渲一条，ffprobe 确认分辨率/时长，抽帧看画面 |

## 不做

图片裁剪 / 滤镜 / 贴纸、每张图单独控时长、图片顺序的界面拖拽调整（要调顺序就改文件名）。

## 已知的效果上限

这条路的产出质量上限在截图本身：手机端界面、内容密度不宜过高、关键信息尽量落在画面中部。第一批真实截图出来后，需要看着真片回调运镜幅度与停留时长。
